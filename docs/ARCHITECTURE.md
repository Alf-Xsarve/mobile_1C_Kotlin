# Архитектура Kotlin-проекта

Все исходники приложения — `app/src/main/java/kg/accounting/mobile/`.

| Файл / каталог | Назначение |
|---|---|
| `MainActivity.kt` | Android-жизненный цикл, системные отступы, возврат и QR-результат |
| `AppSession.kt` | Подключение, экранный стек, фоновые операции, сохранение состояний |
| `core/Models.kt` | Профиль, период, меню, ресурс и адрес сохранённой записи |
| `core/Json.kt` | Разбор JSON без изменения исходного ответа |
| `core/CatalogDraft.kt` | Проверка и формирование трёх POST-запросов справочников |
| `core/UserPreferences.kt` | Избранное, история, списки, раскладки реквизитов |
| `data/Transport.kt` | HttpURLConnection, Basic, таймауты, ограничения размеров и ошибки |
| `data/ODataClient.kt` | Списки, чтение по составному ключу, создание и запрет повторов |
| `data/JournalReader.kt` | Слияние отсортированных страниц нескольких видов документов |
| `data/MetadataModel.kt` | XML-типы, наследование, связи, коллекции и типы строк таблиц |
| `data/ReferenceResolver.kt` | Расшифровка ссылок, кеш на 5 минут / 2000 подписей |
| `data/SecureStore.kt` | AES-GCM, Android Keystore, шифрованные SharedPreferences |
| `ui/Ui.kt` | Общие компоненты интерфейса и цвета |
| `ui/AppScreens.kt` | Вход, главное меню, боковая панель, избранное и история |
| `ui/RecordsUi.kt` | Папки, периоды, поиск, пагинация и выбор элементов |
| `ui/FormUi.kt` | Формы контрагента, номенклатуры, склада и выбор ссылок |
| `ui/CardUi.kt` | Реквизиты, вложенные таблицы, копирование и исходный JSON |
| `ui/SettingsUi.kt` | Тема, масштаб, очистка и переключатели памяти |
| `ui/QrActivity.kt` | Камера, разрешения и однократное чтение QR |
| `app/src/main/assets/schema.json` | Дерево меню и подтверждённые имена коллекций 1С |

## Порядок изучения

1. `MainActivity` → `AppSession`: как запускается приложение и выбирается вход/меню.
2. `Models` и `schema.json`: какие объекты доступны и как строится навигация.
3. `RecordsUi` → `ODataClient`: чтение страницы, период и фильтр родителя.
4. `CardUi` → `MetadataModel` → `ReferenceResolver`: представление ссылок.
5. `FormUi` → `CatalogDraft` → `ODataClient.create`: безопасная запись.
6. `UserPreferences` и `SecureStore`: локальные настройки.

## Принятые решения

Android Views выбраны для самостоятельного Android-приложения с небольшим числом
зависимостей. Списки используют ListView с адаптером; операции сети — отдельный пул
потоков. Результаты публикуются в главный поток. Сеанс сохраняется при пересоздании
Activity, старый ответ от другого подключения отбрасывается по поколению сеанса.

Клиент не получает пароли через справочник пользователей: он проверяет введённые
реквизиты HTTP-запросом с Basic и требует настоящий список OData, а не просто HTTP 200.
Оригинальные ключи сохраняются в JSON; расшифровка создаёт отдельное представление.
Произвольные navigation URL из ответа сервера не исполняются.

GUID-кавычки кодируются как `%27`. Отбор периода использует `year/month/day` и
включает оба крайних дня. Поиск не добавляет `substringof` или `tolower` к запросам.
В журналах курсоры обновляются только после успешной сборки страницы. Если ключ
регистра неоднозначен, история просит открыть запись из списка вместо выбора первой.

POST получает заранее назначенный `Ref_Key`. При обрыве связи или HTTP 5xx результат
считается неизвестным: форма не отправляет запрос снова и предлагает GET-проверку.
После подтверждённого создания открывается карточка, а исходный список обновляется.

Настройки не связаны с паролем и сохраняются для адреса+логина. Выход удаляет профиль,
а предпочтения базы остаются для следующего входа. Полные JSON карточек не сохраняются
на диск. Шифрованные записи дополнительно привязаны к их имени через AES-GCM AAD.
