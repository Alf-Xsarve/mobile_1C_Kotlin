# Данные 1С для Android · Kotlin 1.0.0

Самостоятельный нативный Android-проект на **Kotlin и Android Views**. Flutter и Dart
для разработки и запуска не требуются. Перенесены функции Flutter-версии 1.1.0.
Прежний проект: [mobile_1C](https://github.com/Alf-Xsarve/mobile_1C).

## Возможности

- Первый вход вручную или сканированием QR. После QR вход выполняется автоматически;
  ручная форма по умолчанию свёрнута. Профиль сохраняется на телефоне, «Выйти» удаляет его.
- Боковое меню: банк и касса, покупка-продажа, склад, производство с тремя подменю,
  основные средства и НМА, зарплата, кадры. Состав и сопоставления коллекций перенесены
  из предыдущего проекта; 100 пунктов данных, объединённые журналы и два справочника выбора.
- Справочники с папками `Parent_Key`, включая товары в корне и вложенные группы.
- Документы и периодические регистры с включительным периодом. Поиск локальный,
  постраничная загрузка по 50 строк. Неподдержанные обработки 1С показывают пояснение.
- Карточки, все полученные табличные части и исходный JSON. Ссылки расшифровываются
  по `$metadata`, в том числе через `*_RowType` и отдельную сущность табличной части.
- Создание контрагентов, номенклатуры и складов с выбором папки. В номенклатуре:
  единица из `Catalog_КлассификаторЕдиницИзмерения`, ВЭД из `Catalog_ВЭД`.
- Избранное разделов и карточек, последние 30 карточек, память периода, папки, поиска
  и положения списка, скрытие реквизитов по типу, копирование значений, светлая/тёмная/
  системная тема и размер текста 85–145% с учётом системного масштаба.

Повторное открытие истории перечитывает запись с текущими правами 1С. На телефоне
хранятся ссылки и подписи, без автономной копии всех бухгалтерских данных.

## Открыть проект

```sh
git clone https://github.com/Alf-Xsarve/mobile_1C_Kotlin.git
cd mobile_1C_Kotlin
```

В Android Studio выберите **Open** и корень с `settings.gradle.kts`. Дождитесь Gradle
Sync, выберите эмулятор или телефон и запустите конфигурацию `app`.

Требования: **Android 8.0+ (API 26)**, Android SDK 36, JDK 17+ (подходит JBR Android Studio).
Gradle Wrapper 9.3.1 включён в репозиторий. AGP 9.1.0 использует встроенный Kotlin 2.2.10.
На другом компьютере Android Studio создаст собственный `local.properties`;
локальные пути, ключи подписи и учётные данные в Git не включены.

```powershell
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug
# При подключённом эмуляторе или телефоне:
.\gradlew.bat connectedDebugAndroidTest
```

На macOS/Linux: `chmod +x gradlew`, затем `./gradlew ...`.
APK: `app/build/outputs/apk/debug/app-debug.apk`. Сборка `debug` предназначена для
установки и проверки; для публикации потребуется ваш release-ключ подписи.
GitHub Actions также собирает APK и прикрепляет его к успешному запуску workflow.

## Подключение к 1С

Укажите базовый адрес, например `https://odata.example.com/base/odata/standard.odata/`,
логин и пароль пользователя 1С. Для Android-эмулятора адрес компьютера — `10.0.2.2`;
`localhost` на телефоне относится к самому телефону.

Совместимый с прежним приложением QR-код содержит JSON:

```json
{
  "type": "accounting_1c_connection",
  "version": 1,
  "odataUrl": "https://odata.example.com/base/odata/standard.odata/",
  "username": "example-user",
  "password": "example-password"
}
```

QR содержит пароль: передавайте его только предназначенному пользователю.
Приложение использует HTTP Basic и обычную проверку TLS-сертификатов. HTTP разрешён
для существующей локальной публикации, HTTPS поддерживается без отключения проверки.
Перенаправления запросов с авторизацией не выполняются.

Данные подключения и настройки шифруются AES-GCM с ключом Android Keystore.
Резервное копирование приложения отключено. Настройки базы разделены по адресу
и логину; тема и размер текста общие для устройства. Приложение имеет отдельный
идентификатор `kg.accounting.mobile` и устанавливается рядом с Flutter-версией.
Настройки из Flutter автоматически не импортируются: используйте тот же QR-код.

## Структура и ограничения

[Карта файлов и архитектура](docs/ARCHITECTURE.md) · [Проверки и сценарии](docs/TESTING.md).

Состав `app/src/main/assets/schema.json` основан на ранее подтверждённых метаданных
вашей конфигурации. Отличающиеся конфигурации могут требовать обновления сопоставлений.
Создание документов, проведение, очередь отправки без связи и автономная база ещё
не реализованы — как и в исходной Flutter-версии. Остальные документы открываются
для чтения, создание доступно для трёх указанных справочников.

После неизвестного результата POST повторная отправка блокируется. Приложение
позволяет проверить запись по заранее назначенному UUID, чтобы избежать дублей.
Окончательные требования к полям и права определяет 1С.

Сканирование использует [ZXing Android Embedded](https://github.com/journeyapps/zxing-android-embedded)
(Apache-2.0). Хранение ключей следует [Android Keystore](https://developer.android.com/privacy-and-security/keystore),
настройка Kotlin — [встроенной поддержке AGP](https://developer.android.com/build/migrate-to-built-in-kotlin).
